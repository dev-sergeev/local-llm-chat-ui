# Замечания, баги и предложения

Каждая проблема или новая функция оформляется отдельным Markdown-файлом.

## Куда добавлять

- новые отчёты: `docs/feedback/open/`;
- завершённые отчёты: `docs/feedback/closed/`;
- демонстрационные примеры: `docs/feedback/examples/`.

Скопируйте [TEMPLATE.md](TEMPLATE.md) в `open/` и заполните все обязательные поля.

## Имена файлов

```text
BUG-YYYY-MM-DD-short-name.md
IMPROVEMENT-YYYY-MM-DD-short-name.md
FEATURE-YYYY-MM-DD-short-name.md
```

Один файл должен описывать только одну проблему или функцию.

## Минимальные требования

Для бага укажите:

1. версию проекта и окружение;
2. точные шаги воспроизведения;
3. фактический и ожидаемый результат;
4. влияние на пользователя;
5. безопасный фрагмент лога, HTTP-ответ или скриншот;
6. критерии, по которым можно принять исправление.

Для улучшения или функции опишите пользовательскую проблему, желаемое поведение, границы задачи и критерии готовности.

Перед отправкой желательно проверить актуальный `main` и выполнить:

```bash
uv sync --extra test
uv run ./scripts/test.sh
```

Не прикладывайте токены, содержимое `.env`, приватные URL, полную базу `.data/chat.db` или конфиденциальные сообщения.
