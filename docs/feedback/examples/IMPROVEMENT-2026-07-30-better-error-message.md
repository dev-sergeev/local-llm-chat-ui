# [EXAMPLE][IMPROVEMENT] Показывать понятную причину ошибки подключения

> Демонстрационный пример. Текущее поведение необходимо проверить перед созданием реальной задачи.

## Карточка

- **Тип:** улучшение
- **Статус:** пример
- **Приоритет:** P2
- **Компонент:** UI / профили / HTTP
- **Версия:** `main @ <commit SHA>`

## Краткое описание

При неуспешной проверке профиля пользователь должен понимать класс проблемы: авторизация, недоступный сервер, TLS, timeout, rate limit или неправильный `Model ID`. При этом UI и лог не должны раскрывать токен или приватный URL.

## Пользовательский сценарий

1. Открыть форму профиля.
2. Указать OpenAI-compatible endpoint с просроченным токеном.
3. Нажать «Проверить».
4. Получить краткое сообщение с категорией ошибки и безопасным следующим действием.

## Фактический результат

Заполнить после проверки актуального `main`: точный текст сообщения, HTTP-код и поведение формы.

## Ожидаемый результат

Например, для `401` или `403`:

```text
Авторизация отклонена. Проверьте токен и права доступа.
```

Для timeout:

```text
Сервер модели не ответил вовремя. Проверьте адрес, сеть и доступность API.
```

## Предлагаемое решение

В HTTP-слое возвращать стабильный безопасный `error.code`, а в UI сопоставлять его с коротким русским сообщением. Не показывать исходное исключение провайдера пользователю.

**Не входит в задачу:** автоматическое исправление профиля и вывод полного ответа внешнего API.

## Критерии готовности

- [ ] Различаются минимум auth, timeout/network, TLS, `429` и server error.
- [ ] Ответ содержит безопасный код и понятное действие пользователя.
- [ ] Токен, приватный URL и тело сообщения не попадают в UI или лог.
- [ ] Неизвестная ошибка имеет нейтральный fallback.
- [ ] HTTP- и frontend-тесты покрывают сопоставление ошибок.
