# [EXAMPLE][BUG] Очередь не продолжается после успешного retry

> Демонстрационный пример. Проблема не подтверждена и не является открытым дефектом.

## Карточка

- **Тип:** баг
- **Статус:** пример
- **Приоритет:** P1
- **Компонент:** генерация и retry / очередь
- **Версия:** `main @ <commit SHA>`

## Краткое описание

После ошибки активной генерации пользователь нажимает «Повторить». Повтор завершается успешно, но следующее сохранённое сообщение остаётся в состоянии `queued` и не запускается автоматически.

## Окружение

- **ОС и версия:** Windows 11 24H2
- **Python:** 3.13.x
- **Способ установки:** `uv`
- **Браузер:** Chrome
- **Запуск:** `uv run local-llm-chat`
- **Формат профиля:** `openai`
- **Streaming у API:** нет
- **Model ID:** `test-model`

## Шаги воспроизведения

1. Создать диалог с тестовым OpenAI-compatible профилем.
2. Отправить сообщение A и во время ответа добавить сообщение B в очередь.
3. Имитировать временную ошибку `500` для сообщения A.
4. Вернуть провайдер в рабочее состояние и нажать «Повторить».
5. Дождаться успешного ответа на сообщение A.
6. Проверить статус сообщения B.

**Воспроизводимость:** всегда в тестовом сценарии.

## Фактический результат

Повтор A получает статус `succeeded`, но B остаётся в `queued` до перезапуска сервиса или нового действия пользователя.

## Ожидаемый результат

После успешного повтора A сообщение B автоматически активируется и получает контекст с ответом A.

## Материалы для диагностики

- **Лог:** приложить строки со статусами generation ID без текста сообщений и параметров профиля.
- **HTTP:** `POST /api/generations/{id}/retry`, затем `GET /api/conversations/{id}`.

## Влияние и обходной путь

- **Влияние:** пользователь считает, что сообщение потеряно; FIFO-очередь фактически останавливается.
- **Обходной путь:** перезапустить сервис и повторно открыть диалог.
- **Риск данных:** сообщение сохраняется, но не выполняется автоматически.

## Предлагаемое решение

После успешного retry запускать тот же атомарный механизм активации следующего сообщения, который используется после обычного успешного завершения генерации.

## Критерии готовности

- [ ] После успешного retry автоматически активируется ровно одно следующее сообщение.
- [ ] Его контекст содержит успешный ответ предыдущей генерации.
- [ ] Параллельные retry не создают две активные генерации.
- [ ] Сценарий покрыт behavioral-тестом `GenerationCoordinator` или `ChatApplication`.
- [ ] `uv run ./scripts/test.sh` проходит.
