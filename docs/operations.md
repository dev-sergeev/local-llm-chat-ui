# Эксплуатация в закрытом контуре

## Подготовка поставки

Репозиторий содержит готовый `wheelhouse/` для CPython 3.11, Linux x86_64 и glibc 2.17+. Команда `./scripts/build-wheelhouse.sh` кросс-загружает полностью зафиксированный набор из `requirements-linux-py311.lock` и создаёт относительный `MANIFEST.sha256`. Выполняйте её только там, где package index разрешён политикой организации.

Переносимый комплект включает весь репозиторий, содержимое `wheelhouse/`, но не рабочие `.env` и `.data` другой машины. На целевом компьютере `./start.sh` проверяет все SHA-256, создаёт `.venv`, использует `pip --no-index --find-links wheelhouse` и завершает установку командой `pip check`.

## Запуск и остановка

```bash
./start.sh
./start.sh --port 9000
./start.sh --no-browser
```

По умолчанию сервис слушает только `127.0.0.1:8765`. Внешний bind намеренно запрещён. Остановка — `Ctrl+C` или `SIGTERM`; новые ответы после отмены не записываются. Кнопка «Остановить» немедленно меняет локальное состояние и отбрасывает поздний ответ, но синхронный запрос–ответ transport может занимать свой ограниченный слот до сетевого завершения или тайм-аута.

Поддерживаемые переменные запуска:

- `DATALAB_PORT` — порт по умолчанию;
- `DATALAB_PYTHON_BIN` — путь к Python, которым создаётся `.venv`;
- `DATALAB_VENV_DIR` — переопределяемый путь к виртуальному окружению для изолированной проверки поставки;
- `SSL_CERT_FILE` — системный CA bundle для закрытого TLS-контура, если его поддерживает установленный HTTP stack;
- стандартные proxy-переменные Python/HTTP-клиента — только если они требуются банковской сетью.

Пути можно изменить аргументами `--env-file` и `--data-dir`. Для штатной эксплуатации рекомендуется оставить локальные `.env` и `.data/` в корне проекта.

## Данные

SQLite работает в WAL-режиме. Главный файл и sidecar-файлы получают права `0600`; каталог `.data` — `0700`. `.env` обновляется через временный файл, `fsync`, атомарный `os.replace` и `fsync` родительского каталога, сохраняя посторонние переменные вне управляемого блока. При чтении права существующего файла приводятся к `0600`. Значения управляемого блока записываются в безопасных POSIX single quotes: `$`, обратные кавычки и подстановки команд остаются буквальными даже при чтении файла через shell.

Для резервной копии:

1. Остановите сервис.
2. Скопируйте `.env` и весь каталог `.data/` на разрешённый зашифрованный носитель.
3. Ограничьте доступ к копии: `.env` содержит реальные токены.

Для восстановления остановите сервис, верните оба объекта на прежнее место, проверьте права и снова выполните `./start.sh`. Приложение не удаляет автоматически повреждённую базу; при ошибке сохраните её копию для диагностики.

## Логи и диагностика

`.data/app.log` ротируется при размере около 1 МБ, хранятся две предыдущие версии. Лог содержит старт/остановку, локальный путь запроса и класс неожиданной ошибки, но не JSON-тела, ответы модели, URL профиля или токены.

Типовые ситуации:

- «порт занят» — запустите с другим `--port`;
- «LLM-библиотеки не найдены» — положите полный набор wheels в `wheelhouse/`;
- ошибка авторизации — проверьте формат профиля, токен, URL и `Model ID`;
- ошибка сертификата — передайте корпоративный CA через доверенную системную конфигурацию или `SSL_CERT_FILE`;
- генерация «прервана» — процесс завершился во время запроса; нажмите «Повторить» вручную;
- сообщение «требует внимания» в очереди — выбранный профиль удалён или изменён после отправки; уберите запись и отправьте текст с актуальным профилем;
- ошибка активной генерации — очередь этого диалога намеренно приостановлена до успешного повтора, чтобы не потерять контекст;
- SQLite не открывается — проверьте права `.data`, свободное место и целостность резервной копии.

## Обновление

Остановите сервис, сохраните резервную копию `.env` и `.data`, замените отслеживаемые файлы репозитория и заново подготовьте `.venv`, если изменился `requirements.txt`. Локальные файлы исключены из Git и не должны перезаписываться обновлением кода.
