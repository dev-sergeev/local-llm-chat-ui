# Local LLM Chat UI

Loopback-сервис с web-чатом для работы с LLM через GigaChat и OpenAI-compatible API. Поддерживает несколько профилей моделей, ветвящуюся историю, редактирование сообщений, регенерацию, смену профиля и восстановление после сбоев. Ответы отображаются как безопасный Markdown с таблицами и блоками кода; текст и код можно копировать из интерфейса.

## Быстрый запуск

Требования: Python 3.10 или новее с поддержкой текущих версий зависимостей и современный браузер. Рекомендуемый способ установки и запуска использует [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run local-llm-chat
```

`uv` создаст локальное виртуальное окружение, установит зависимости и запустит сервис на `http://127.0.0.1:8765`. Браузер откроется автоматически.

Нужную версию Python можно выбрать явно, например: `uv sync --python 3.13`. Если старая `.venv` доступна только для чтения, создайте новое окружение в другом каталоге:

```bash
export UV_PROJECT_ENVIRONMENT="$PWD/.uv-venv"
uv sync --python 3.13
uv run local-llm-chat
```

Если вы используете `pip`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
local-llm-chat
```

При первом входе:

1. Нажмите «Добавить профиль».
2. Укажите название, формат API, URL, токен и `Model ID`.
3. Сохраните профиль и нажмите «Проверить».
4. Создайте диалог и отправьте сообщение.

Другой порт или запуск без автоматического открытия браузера:

```bash
uv run local-llm-chat --port 9000 --no-browser
```

Port-forwarding и preview/reverse-прокси работают без отдельного флага, в том числе при подмене `Host` и `Origin`. Python-процесс слушает loopback; внешний адрес и круг пользователей определяются настройкой прокси.

## Поддерживаемые подключения

Каждый профиль имеет отдельное отображаемое название и четыре параметра подключения:

- `format`: `gigachat` или `openai`;
- `base_url`: адрес API;
- `token`: локальный секрет;
- `model_id`: значение параметра `model` в запросе.

GigaChat вызывается через `langchain_gigachat.GigaChat` с токеном в `access_token`; OpenAI-compatible — через `langchain_openai.ChatOpenAI` с `api_key`. Оба адаптера получают `base_url`, `model` и отключённые внутренние повторы — общей политикой повторов управляет приложение.

API без поддержки streaming работают в режиме запрос–ответ. Интерфейс показывает честное ожидание и затем полный ответ, не имитируя потоковую передачу. Пока модель отвечает, поле ввода остаётся доступным: новые сообщения сохраняются в устойчивую FIFO-очередь и выполняются последовательно с правильным контекстом. Кнопка «Остановить» сразу прекращает ожидание и запрещает сохранение позднего ответа. Внутренний транспорт допускает добавление настоящих чанков позже.

## Локальные данные и секреты

- `.env` — профили моделей и токены, права `0600`, исключён из Git;
- `.data/chat.db` — SQLite-история и ветки, права `0600`, исключён из Git;
- `.data/app.log` — ротируемый технический лог без тел запросов и токенов;
- `.env.example` — безопасный шаблон без профилей и ключей.

Сервис привязан только к loopback и принимает изменяющие запросы только как JSON. Прикладной аутентификации и ограничений по `Host`/`Origin` нет: любой пользователь, которому прокси открыл адрес, получает доступ к UI, истории и настройкам моделей. Защиты от DNS rebinding также нет; CORS отдельно не включается. Markdown безопасно экранируется. Локальный `.env` не зашифрован, поэтому доступ к адресу и файлам проекта следует задавать средствами ОС и прокси.

Таблица стилей содержит fallback-значения для динамической высоты viewport, `color-mix()` и Safari backdrop blur, а JavaScript не зависит от `String.prototype.replaceAll` и не падает при недоступном `localStorage`. Страница также нормализует proxy-URL без завершающего `/`, чтобы CSS и JavaScript загружались из правильного каталога.

## Отказоустойчивость

- общий дедлайн генерации — не более 10 минут;
- до трёх попыток с exponential backoff и jitter;
- повторяются сетевые ошибки, `408`, `429` и `5xx`;
- ошибки авторизации и другие `4xx` не повторяются;
- отменённый или поздний ответ не записывается;
- сообщения, отправленные во время ответа, сохраняются в SQLite-очереди и не теряются при перезапуске;
- ошибка генерации приостанавливает её очередь до успешного повтора, а отмена запускает следующее сообщение;
- одновременно выполняются не более четырёх генераций и четырёх внешних вызовов; зависший транспорт не создаёт неограниченное число потоков;
- незавершённая операция после рестарта получает статус «прервана» и кнопку повтора;
- ошибка одного запроса не останавливает сервис.

## Проверка репозитория

```bash
uv sync --extra test
uv run ./scripts/test.sh
```

Набор включает Python behavioral/integration/smoke-тесты, Node-тест безопасного Markdown и проверку синтаксиса frontend. Python-тесты используют настоящие временные `.env`, SQLite и localhost-сервер; заменяется только внешний LLM.

## Структура

```text
src/datalab_chat/
├── application.py      # пользовательские сценарии
├── profiles.py         # атомарный каталог профилей в .env
├── memory.py           # SQLite, ветки и версии
├── generation.py       # дедлайн, повторы, отмена, recovery
├── gateways.py         # GigaChat/OpenAI LangChain-адаптеры
├── web.py              # loopback HTTP и защитные заголовки
└── static/             # полностью локальный browser UI
```
